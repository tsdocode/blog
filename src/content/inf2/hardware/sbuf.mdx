SBUF (State Buffer) is the NeuronCore's main working memory: 24 MiB of on-chip SRAM. There are **no caches**.
Data reaches SBUF only when your kernel issues a <T id="hardware/dma">DMA</T> from HBM, stays exactly as long
as your kernel keeps it, and goes back to HBM only when you write it out.

## Partitions

SBUF is split into 128 **partitions**. Each engine instruction processes many partitions in parallel, the same
access pattern in each — partition `p` feeds lane `p`. That makes the partition axis the parallel axis and the
free axis (bytes within a partition) the sequential one. See
<T id="programming/partition-and-free-axes">partition and free axes</T>.

Two rules follow:

- **Pick what goes on partitions.** For a matmul the contraction dimension must be on partitions; for a row-wise
  softmax the rows must be. Kernels often keep the same data in different layouts for different steps.
- **Crossing partitions is expensive.** The compute engines cannot move data between partitions except through the
  <T id="hardware/tensor-engine">Tensor Engine</T> (a transpose is a matmul with the identity) or DMA.

## Who can touch it

DMA reads and writes SBUF; the Tensor Engine reads it; Vector, Scalar and GpSimd read and write it. SBUF can feed
Vector, Scalar and Tensor at full bandwidth simultaneously; Vector and GpSimd cannot access it at the same time.

## Budgeting 192 KiB per partition

Everything a kernel keeps on chip must fit in 192 KiB per partition, and the compiler spills to HBM when it does not.
For a 28-layer transformer step you cannot keep all weights resident, so the usual pattern is to stream weights
block by block through SBUF while activations stay resident.
