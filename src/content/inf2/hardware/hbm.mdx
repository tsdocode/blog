HBM is the chip's device memory: two stacks, 32 GiB in total, shared by both NeuronCores. Everything that does not
fit on chip lives here — model weights, KV caches, codec state — and every kernel input and output starts and
ends here. Compute engines never read HBM directly; <T id="hardware/dma">DMA</T> engines copy data into
<T id="hardware/sbuf">SBUF</T> first.

## What you can actually get

I measured sustained HBM → SBUF bandwidth with a kernel that streams a 67 MB tensor in large, contiguous tiles:
**257 GB/s on one core** and about **508 GB/s with both cores streaming at once** — 62% of the 820 GB/s spec, and
the cores barely slow each other down. For comparison, an NVIDIA L4 lists 300 GB/s for the whole GPU.

That per-core number is the one that matters for decode, because a decode step must read every weight once:

| Workload (per core) | Bytes per step | Floor at 257 GB/s | Measured |
| --- | ---: | ---: | ---: |
| Talker, 28 layers, dense part | 2.82 GB | 11.0 ms | 11.0 ms |
| Talker KV cache, 32 streams | ~0.7 GB | ~2.7 ms | (inside attention) |
| Code predictor, 16 depth steps | ~2.6 GB | ~10 ms | 14.3 ms per frame |

## Why the spec is higher than what one core sees

A core reaches HBM through its 16 DMA engines (27 GiB/s each), and the achieved rate depends heavily on how
large and how contiguous each transfer is (see <T id="hardware/dma">DMA</T>). The full 820 GB/s is a
chip-level figure for both cores and both stacks.
