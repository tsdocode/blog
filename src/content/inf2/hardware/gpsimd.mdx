GpSimd is the general-purpose corner of the NeuronCore: **eight programmable processors**, each a 512-bit vector
machine that can run arbitrary C/C++. Each one is wired to 16 <T id="hardware/sbuf">SBUF</T> partitions, so
together they cover all 128.

## What it is used for

- **Custom operators** and the long tail of ops the fixed-function engines do not have.
- **Generating DMA descriptors at runtime** for some data-dependent transfers.
- **A third pair of hands** for simple element-wise work (casts, iota, memset) when Vector and Scalar are busy.

## Caveats on gen2

GpSimd **cannot read PSUM**, so it cannot evict matmul results. In our kernels the compiler also rejected some fp32
tensor-tensor operations on it. It also shares SBUF access with the Vector Engine — the two cannot use it at the
same time — so moving work from Vector to GpSimd does not always help.

The codec's fp32 → bf16 casts are pinned to GpSimd (`CAST_ENGINE = nisa.engine.gpsimd`) to take them off the
Vector Engine, which was the bottleneck at audio sample rate.
