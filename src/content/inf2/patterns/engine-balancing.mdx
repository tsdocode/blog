Because each engine runs its own instruction stream, a kernel's time is roughly the time of its busiest engine,
not the sum. The useful question for any slow kernel is "which engine is at 90%?" — and the answer is often not the
Tensor Engine.

## What can move where

| Work | Natural engine | Can also run on |
| --- | --- | --- |
| matmul, transpose, cross-partition sum | Tensor | — |
| two-input element-wise, masks, reductions | Vector | GpSimd (limited) |
| one-input element-wise, `exp`, `silu`, `rsqrt` | Scalar | Vector (simple arithmetic) |
| SBUF → SBUF copy | Vector | Scalar (`activation(op=copy)`), GpSimd |
| cast fp32 → bf16 | Vector | Scalar, GpSimd |
| PSUM eviction | Vector | Scalar (not GpSimd: no PSUM access) |

## Tricks that remove work entirely

- **Fuse into the eviction.** The copy out of PSUM can carry a bias, residual add, scale or activation.
- **Fold an add into a matmul.** If the next op is a convolution or linear, `conv(x + s) = conv(x) + conv(s)`: feed
  `x` and `s` as two accumulating matmuls instead of spending a Vector pass on the add — the Tensor Engine usually
  has slack in memory-bound kernels.
- **Fuse the scale.** Scalar's `f(x · scale + bias)` absorbs a preceding multiply-add for free.
